## C3 — Verify JDK Installation

### ⚠️ CRITICAL: Open a NEW Command Prompt

**Close ALL existing Command Prompt windows** (if any are open).

**Open a brand new Command Prompt:**

```
Start Menu → Type: cmd → Press: Enter
```

> **Why a new window?** Environment variable changes (PATH, JAVA_HOME) only apply to NEW command prompt windows. Old windows still use the old PATH.

### Test 1: java -version

```cmd
java -version
```

**Expected output:**

```
openjdk version "17.0.13" 2024-10-15
OpenJDK Runtime Environment Temurin-17.0.13+11 (build 17.0.13+11)
OpenJDK 64-Bit Server VM Temurin-17.0.13+11 (build 17.0.13+11, mixed mode, sharing)
```

> **Note:** The exact version numbers (17.0.13, 17.0.12, etc.) may differ slightly depending on which release you downloaded. That's fine — as long as it starts with `17.0` and says `Temurin`.

### Possible Error C3.1: "'java' is not recognized as an internal or external command"

```
Why:    Java is not in the system PATH.

Fix:    
    Step 1: Close this Command Prompt. Open a NEW one.
        → Sometimes the old window doesn't pick up PATH changes
        → Start Menu → cmd → New window
    
    Step 2: If still fails in new window, set PATH manually.
        → Open PowerShell (Admin):
           Start Menu → Search "PowerShell"
           → Right-click → Run as administrator
        
        Run these commands one by one:
        
        Command 1 (find the JDK path):
        
            Get-ChildItem "C:\Program Files\Eclipse Adoptium\"
            
        → Look at the output. You'll see a folder like:
            jdk-17.0.13.11-hotspot
            or jdk-17.0.12.7-hotspot
        
        → Copy the EXACT folder name.
        
        Command 2 (set JAVA_HOME):
        
            [Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot", "Machine")
        
        → Replace jdk-17.0.13.11-hotspot with YOUR exact folder name.
        
        Command 3 (add to PATH):
        
            $currentPath = [Environment]::GetEnvironmentVariable("Path", "Machine")
            $javaBin = "C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot\bin"
            [Environment]::SetEnvironmentVariable("Path", "$currentPath;$javaBin", "Machine")
        
        → Replace the path with YOUR exact JDK folder name.
        
        Command 4 (verify):
        
            [Environment]::GetEnvironmentVariable("JAVA_HOME", "Machine")
            
        → Should output: C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot
        
        → Close PowerShell
        → Open a NEW Command Prompt
        → Run: java -version
```

    Step 2: If javac.exe exists but command doesn't work:
        → Follow the PATH fix in Error C3.1 above
        → Make sure the bin directory is added to PATH

## C6 — Install Tomcat as a Windows Service

### Why Install as a Service?

```
Without service:  Tomcat only runs when you manually start it.
                  If the VM restarts, you must manually start it again.
                  
As a service:     Tomcat starts automatically when the VM boots.
                  It runs in the background like SQL Server.
                  We can start/stop it from Services panel.
```

### What to Do

**Open Command Prompt as Administrator:**

## C8 — Configure Tomcat Manager Credentials

### Why This Step?

The Tomcat Manager is a web interface for deploying and managing web applications. By default, no users are configured, so you can't log in. We need to add a user with manager access.

### What to Do

**Open the Tomcat users configuration file in Notepad:**

```
Start Menu → Search: Notepad → Open Notepad

C:\apache-tomcat-10.1.34\conf\

"Text Documents (*.txt)" → "All Files (*..*)

Click: Open
```

### What You See

```xml
<?xml version="1.0" encoding="UTF-8"?>
<tomcat-users xmlns="http://tomcat.apache.org/xml"
              xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
              xsi:schemaLocation="http://tomcat.apache.org/xml tomcat-users.xsd"
              version="1.0">
<!--
  <role rolename="tomcat"/>
  <role rolename="role1"/>
  <user username="tomcat" password="<must-be-changed>" roles="tomcat"/>
  <user username="both" password="<must-be-changed>" roles="tomcat,role1"/>
  <user username="role1" password="<must-be-changed>" roles="role1"/>
-->
</tomcat-users>
```

### Edit the File

**Replace the ENTIRE content** between `<tomcat-users ...>` and `</tomcat-users>`:

**Delete everything between the opening tag and closing tag**, then paste this:

```xml
  <role rolename="manager-gui"/>
  <role rolename="manager-script"/>
  <role rolename="admin-gui"/>
  <role rolename="admin-script"/>
  <user username="admin" password="tomcat123" roles="manager-gui,manager-script,admin-gui,admin-script"/>
```

**The complete file should look EXACTLY like this:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<tomcat-users xmlns="http://tomcat.apache.org/xml"
              xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
              xsi:schemaLocation="http://tomcat.apache.org/xml tomcat-users.xsd"
              version="1.0">

  <role rolename="manager-gui"/>
  <role rolename="manager-script"/>
  <role rolename="admin-gui"/>
  <role rolename="admin-script"/>
  <user username="admin" password="tomcat123" roles="manager-gui,manager-script,admin-gui,admin-script"/>

</tomcat-users>
```

## C9 — Remove Manager IP Restriction

### Why This Step?

By default, Tomcat Manager only allows access from `localhost` (127.0.0.1). We need to remove this restriction so we can access it from outside the VM later.

### What to Do

**In Notepad (still inside the VM):**

```
File → Open → Navigate to:
C:\apache-tomcat-10.1.34\webapps\manager\META-INF\

Change file type to "All Files (*.*)"
Click: context.xml
Click: Open
```

### What You See

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Context antiResourceLocking="false" privileged="true" >
  <CookieProcessor className="org.apache.tomcat.util.http.Rfc6265CookieProcessor"
                   sameSiteCookies="strict" />
  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
         allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
  <Manager sessionsAttributeValueClassNameFilter="java\.lang\.(?:Boolean|Integer|Long|Number|String)|org\.apache\.catalina\.filters\.CsrfPreventionFilter\$LruCache(?:\$1)?|java\.util\.(?:Linked)?HashMap"/>
</Context>
```

### Comment Out the IP Restriction

**Find this line:**

```xml
  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
         allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
```

**Wrap it with `<!--` and `-->`:**

```xml
  <!--
  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
         allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
  -->
```

**The complete file should look like this:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Context antiResourceLocking="false" privileged="true" >
  <CookieProcessor className="org.apache.tomcat.util.http.Rfc6265CookieProcessor"
                   sameSiteCookies="strict" />
  <!--
  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
         allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
  -->
  <Manager sessionsAttributeValueClassNameFilter="java\.lang\.(?:Boolean|Integer|Long|Number|String)|org\.apache\.catalina\.filters\.CsrfPreventionFilter\$LruCache(?:\$1)?|java\.util\.(?:Linked)?HashMap"/>
</Context>
```

**Save:** `Ctrl + S`

### Do the Same for Host Manager

```
File → Open → Navigate to:
C:\apache-tomcat-10.1.34\webapps\host-manager\META-INF\context.xml
```

**Find the same `<Valve` line and comment it out the same way:**

```xml
  <!--
  <Valve className="org.apache.catalina.valves.RemoteAddrValve"
         allow="127\.\d+\.\d+\.\d+|::1|0:0:0:0:0:0:0:1" />
  -->
```

**Save:** `Ctrl + S`
