# Service Bus Brokered Messaging using Topics (C#)

---

## What this experiment is

A **Topic** is a message service in Azure where **one message can reach many receivers at the same time**.

Think of a college notice board: one person pins one notice, but every student reads their own copy. In Azure, the notice board is called a **Topic**, and each student's personal copy is called a **Subscription**. Every subscription gets its own copy of every message. This style of messaging is called **Publish / Subscribe**.

---

## How it works

```
   Website (Publisher)
          │  sends 1 message
          ▼
      Topic : orderstopic
          │  Azure makes a copy for each subscription
   ┌──────┴──────────┐
   ▼                 ▼
billingsub       shippingsub
   │                 │
Billing app      Shipping app
```

Each subscription keeps its own message count and its own copy of the message.

---

## Why it is useful in real time

Real example — a customer places an order on a shopping website. The **Billing** team, the **Shipping** team and the **Email** team all need the same order details at the same time. The website publishes the order **once** to a Topic, and each team reads its own copy from its own subscription. No team misses the order, and the website does not have to send the same data three times.

## Part A — Create the Azure things (Portal)

1. Login to **Azure Portal** (portal.azure.com).
2. Create a **Resource group** → name: `exp11-rg`.
3. Search **Service Bus** → **Create**.
   - Resource group: `exp11-rg`
   - Service name: `labservicetopic2026`
     (this is your Service Bus address in the Azure cloud — small letters and numbers only, must be unique)
   - Pricing tier: **Standard** (Basic does **not** support Topics)
   - → **Review + create** → **Create**.
4. Open your Service Bus → **Entities → Topics** → **+ Topic** → name: `orderstopic` → **Create**.
5. Open `orderstopic` → **Subscriptions** → **+ Subscription** → name: `billingsub` → **Create**.
6. Again **+ Subscription** → name: `shippingsub` → **Create**.
7. Go back to the Service Bus → **Shared access policies → RootManageSharedAccessKey** → copy the **Primary Connection String**. You need it in Part D.

## Part D — Code

Open `Program.cs`, delete everything, and paste this:

```csharp
using System;
using Azure.Messaging.ServiceBus;

namespace ServiceBusTopicDemo
{
    internal class Program
    {
        // Paste your connection string here
        const string Conn = "Endpoint=sb://labservicetopic2026.servicebus.windows.net/;SharedAccessKeyName=RootManageSharedAccessKey;SharedAccessKey=YOURKEY";

        const string Topic = "orderstopic";

        static void Main(string[] args)
        {
            var client = new ServiceBusClient(Conn);

            if (args.Length > 0 && args[0] == "read")
            {
                string sub = args.Length > 1 ? args[1] : "billingsub";
                var reader = client.CreateReceiver(Topic, sub);
                var msg = reader.ReceiveMessageAsync().Result;

                if (msg == null) Console.WriteLine(sub + " is empty.");
                else
                {
                    Console.WriteLine(sub + " received: " + msg.Body.ToString());
                    reader.CompleteMessageAsync(msg).Wait();   // deletes this subscription's copy
                }
            }
            else
            {
                var sender = client.CreateSender(Topic);
                sender.SendMessageAsync(new ServiceBusMessage("New order placed")).Wait();
                Console.WriteLine("Message published. Now check Azure Portal.");
            }

            Console.ReadLine();
        }
    }
}
```

**Plain words:**
- `ServiceBusClient` — connects to your Service Bus in Azure.
- `CreateSender(Topic)` + `SendMessageAsync` — publishes one message to the topic; Azure copies it to every subscription.
- `CreateReceiver(Topic, sub)` + `ReceiveMessageAsync` — reads one message from that subscription only. (This line needs **two** names: topic and subscription — that is what makes it a Topic program.)
- `CompleteMessageAsync` — confirms and deletes that subscription's copy only.
- Run with no argument → **publish**. Run with `read` → read `billingsub`. Run with `read shippingsub` → read `shippingsub`.

**Small fix if needed:** if you see a "Could not load file or assembly" error, right-click the project → **Properties** → check **Auto-generate binding redirects** → Save → Build again.

## Part E — Run and Publish

1. Paste your connection string into `Conn`.
2. **Ctrl + F5** (Start Without Debugging).
3. Output:

```
Message published. Now check Azure Portal.
```

---

## Part F — Verify in Azure

1. Azure Portal → **Service Bus** → your service `labservicetopic2026`.
2. **Entities → Topics** → `orderstopic` → **Subscriptions**.
3. You will see **both** `billingsub` and `shippingsub` showing **1** under **Active Message(s)** — one send, two copies.
4. To see the message body: open `billingsub` → **Service Bus Explorer** → **Peek** → select the message → body shows `New order placed`.

---

## Part G — Read the copies from the app

1. **Project → Properties → Debug** → Command line arguments: `read` → **Ctrl + F5**

```
billingsub received: New order placed
```

2. Change arguments to `read shippingsub` → **Ctrl + F5**

```
shippingsub received: New order placed
```

3. Refresh the portal → both counts are back to 0.
