# Azure File Storage — Complete Beginner-Friendly Guide

> **Compatibility:** Visual Studio Community 2022 / 2026 / 2026 Insiders with the **ASP.NET and web development** workload installed, targeting **.NET 8.0 LTS**.

---

## What This Experiment Does (In Plain English)

You will build a simple website that lets you **upload**, **download**, and **delete** files — but instead of storing them on your computer, they are stored in the cloud using **Azure File Shares**. Think of it like your own personal Google Drive, but built from scratch using Azure.

---

## Part 1: Create Your Cloud Storage (Azure Storage Account)

Before writing any code, you need a place in the cloud to store files.

### Step 1.1 — Sign In to Azure

1. Open your browser.
2. Go to **[https://portal.azure.com](https://portal.azure.com)**.
3. Sign in with your Azure account (your university or personal account with an active subscription).

### Step 1.2 — Create a Storage Account

1. Once inside the Azure Portal, look at the top-left corner. Click **"Create a resource"** (it has a plus icon).
2. In the search bar that appears, type **Storage Account** and press Enter.
3. You will see "Storage account" by Microsoft. Click it, then click the **Create** button.

### Step 1.3 — Fill In the Configuration

You will see a form with several tabs. Fill in the **Basics** tab as follows:

| Field | What to Enter | Explanation |
|---|---|---|
| **Subscription** | Select your active subscription | This is the billing account tied to your Azure access |
| **Resource Group** | Click "Create new" → type `LabExperiments` → OK | A resource group is like a folder that groups related Azure resources together |
| **Storage Account Name** | Type a unique name like `filestorage2026` | This must be globally unique, lowercase letters and numbers only, 3–24 characters |
| **Region** | Select the nearest datacenter to you | Closer region = faster access |
| **Performance** | **Standard** | Standard is sufficient for file shares |
| **Redundancy** | **Locally-redundant storage (LRS)** | LRS keeps 3 copies of your data in one datacenter — cheapest option and fine for lab work |

Leave everything else at default values.

### Step 1.4 — Create the Account

1. Click **Review + Create** at the bottom.
2. Wait for the validation to pass (green checkmark).
3. Click **Create**.
4. Wait for deployment to complete (1–2 minutes). You will see a "Your deployment is complete" message.

### Step 1.5 — Copy Your Connection String

This connection string is like a password that lets your code talk to your storage account.

1. Click **Go to resource** (on the deployment complete page).
2. On the left sidebar, under **Security + networking**, click **Access keys**.
3. You will see **key1** and **key2**. Under key1, click **Show** next to the Connection string.
4. Click the **copy icon** next to the connection string.
5. **Paste it somewhere safe** (a Notepad file). You will need it in Part 3.

> **What is a connection string?** It is a single line of text that contains your storage account name, account key, and endpoint — everything your application needs to authenticate and connect to your storage.

> **What is MVC?** MVC stands for **Model-View-Controller**. It is a pattern that separates your application into three parts:
> - **Model** — the data (in our case, file information)
> - **View** — the HTML page the user sees
> - **Controller** — the logic that handles requests (upload, download, delete)

### Step 3.3 — Create the Controller (the Logic)

**File:** `Controllers/FileController.cs` (create this new file, or replace if a `HomeController.cs` exists)

```csharp
using Microsoft.AspNetCore.Mvc;
using Azure.Storage.Files.Shares;
using Azure;

namespace FileWebRole.Controllers
{
    public class FileController : Controller
    {
        private readonly string _conn;

        public FileController(IConfiguration cfg)
            => _conn = cfg.GetConnectionString("AzureFileStorage")!;

        private ShareDirectoryClient GetRoot()
        {
            var share = new ShareClient(_conn, "demoshare");
            share.CreateIfNotExists();
            return share.GetRootDirectoryClient();
        }

        [HttpGet]
        public async Task<IActionResult> Index()
        {
            var root = GetRoot();
            var list = new List<dynamic>();
            await foreach (var item in root.GetFilesAndDirectoriesAsync())
            {
                if (!item.IsDirectory)
                {
                    var fc = root.GetFileClient(item.Name);
                    var props = await fc.GetPropertiesAsync();
                    list.Add(new { Name = item.Name, Size = props.Value.ContentLength });
                }
            }
            return View("~/Views/Home/Index.cshtml", list);
        }

        [HttpPost]
        public async Task<IActionResult> Upload(IFormFile file)
        {
            if (file == null || file.Length == 0) return await Index();
            try
            {
                var root = GetRoot();
                var fc = root.GetFileClient(file.FileName);
                await fc.CreateAsync(file.Length);
                using var stream = file.OpenReadStream();
                await fc.UploadRangeAsync(new HttpRange(0, file.Length), stream);
                ViewBag.Message = "Upload Successful!";
            }
            catch (Exception ex) { ViewBag.Message = $"Upload Failed: {ex.Message}"; }
            return await Index();
        }

        [HttpGet]
        public async Task<IActionResult> Download(string fileName)
        {
            var fc = GetRoot().GetFileClient(fileName);
            var info = await fc.DownloadAsync();
            return File(info.Value.Content, info.Value.ContentType, fileName);
        }

        [HttpGet]
        public async Task<IActionResult> Delete(string fileName)
        {
            try { await GetRoot().GetFileClient(fileName).DeleteAsync(); }
            catch (Exception ex) { ViewBag.Message = $"Delete Failed: {ex.Message}"; }
            return RedirectToAction("Index");
        }
    }
}
```

**Detailed breakdown of each method:**

| Method | What It Does (Line by Line) |
|---|---|
| **Constructor** `FileController(IConfiguration cfg)` | ASP.NET automatically provides `IConfiguration`. We extract the connection string once and store it in `_conn`. |
| **`GetRoot()`** | Creates a `ShareClient` for a file share named `"demoshare"`. Calls `CreateIfNotExists()` so the share is automatically created on first run. Returns the root directory client. |
| **`Index()`** | Lists all items in the share's root directory. For each file (not directory), it gets the file's properties (specifically `ContentLength` for the size) and adds it to a list. Passes the list to the view. |
| **`Upload(IFormFile file)`** | Receives the uploaded file from the form. Two-step process: (1) `CreateAsync(file.Length)` — pre-allocates the exact amount of space on Azure, (2) `UploadRangeAsync(HttpRange(0, file.Length), stream)` — writes the file bytes into that allocated space. This is the **range-based upload** approach. |
| **`Download(string fileName)`** | Finds the file by name, calls `DownloadAsync()` to get the content stream, and returns it as a file download to the browser. |
| **`Delete(string fileName)`** | Finds the file by name and calls `DeleteAsync()` to remove it from the share. Redirects back to Index to refresh the list. |

> **What is range-based upload?** Instead of uploading the whole file in one uncontrolled blob, the code first tells Azure "I need X bytes of space" (`CreateAsync`), then writes the data into that space starting at byte position 0 (`UploadRangeAsync`). This gives precise control over the upload process.

### Step 3.4 — Configure Routing

**File:** `Program.cs` (replace the existing content entirely)

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();
var app = builder.Build();

app.UseStaticFiles();
app.UseRouting();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=File}/{action=Index}/{id?}");

app.Run();
```

**What each line does:**

| Line | Purpose |
|---|---|
| `builder.Services.AddControllersWithViews()` | Registers MVC services (controllers and Razor views) |
| `app.UseStaticFiles()` | Enables serving static files (CSS, JS, images) from wwwroot |
| `app.UseRouting()` | Enables endpoint routing |
| `MapControllerRoute(... pattern: "{controller=File}/{action=Index}/{id?}")` | Sets the default route. When you visit the root URL (`/`), it maps to `FileController.Index()` because `File` and `Index` are the defaults |

## Part 5: Troubleshooting

| Problem | Why It Happens | How to Fix It |
|---|---|---|
| **`403 Forbidden`** error | Your connection string has invalid or expired access keys | Go to Azure Portal → your Storage Account → **Access keys** → click **Regenerate** on key1 → copy the new connection string → update `appsettings.json` → restart the app |
| **"Share not found"** or share doesn't exist | The code uses `CreateIfNotExists()` so this is rare, but verify your connection string is correct | Double-check the connection string in `appsettings.json` has no extra spaces or missing characters |
| **Upload fails for large files** | Azure File Shares have limits on single-operation uploads | The code uses `CreateAsync(file.Length)` to allocate space. For files larger than 4 GB, consider chunked upload (splitting the file into ranges) |
| **Download returns 404** | The `fileName` route parameter does not exactly match the stored file name | File names are **case-sensitive**. Ensure the name in the URL matches exactly |
