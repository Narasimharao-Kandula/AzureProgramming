# Service Bus Queues (Brokered Messaging) in C#

---

## Why we do this experiment

When one program sends data to another program, both must run at the same time. If the receiver is off, the data is lost. This is a problem in real applications.

Azure Service Bus Queue fixes this. The sender puts the message into a queue in the cloud. The message stays there safely. The receiver takes it later, even after many hours. So sender and receiver need not run together.

This experiment teaches that simple idea with a small C# program.

## What this experiment is about

In this experiment we do three small things:

1. Create a **Service Bus Namespace** and a **Queue** in the Azure Portal.
2. Write a small **C# Console App** that sends one message to that queue.
3. Open the Azure Portal again and see the message count go up under **Active Messages**.

That is all. Once this works, the same code can be used for bigger applications.

## Name Ideas (use these if you are not sure what to type)

When Azure asks for a name, beginners often get stuck. Just copy one of these.

| Thing to name | Example names | Simple rules |
|---|---|---|
| **Resource group** | `exp10-rg`, `cloudlab-rg` | Any simple name |
| **Service Bus Namespace** | `labservicebus2026`, `cloudlabsbus01`, `mystudybus01` | 6 to 50 letters/numbers, small letters only, hyphens allowed, must start with a letter, no two hyphens together, must be **unique in all of Azure** |
| **Queue** | `messagesqueue`, `labqueue`, `orderqueue` | Up to 260 characters, small letters/numbers/dash/dot/underscore, must be unique inside your namespace |
| **Project name** | `ServiceBusQueueDemo`, `MyQueueApp` | Any simple name |
| **Connection string name** | `RootManageSharedAccessKey` | Already present in Azure — just copy it |

If a name says "already taken", just add numbers at the end, like `cloudlabsbus02`.

**One small clarification for beginners:** here the word **Namespace** means an address in Azure (a small space in the cloud for your messaging service). It is **not** the same as the `namespace` word used in C# code. Do not mix them.

## Part A — Create the Azure things (Portal)

1. Login to **Azure Portal** (portal.azure.com).
2. Create a **Resource group** → name: `exp10-rg`.
3. Search **Service Bus** → **Create**.
   - Resource group: `exp10-rg`
   - Namespace name: `labservicebus2026` (or any name from the table)
   - Pricing tier: **Basic**
   - → **Review + create** → **Create**.
4. Open your new namespace → **Entities → Queues** → **+ Queue**.
   - Queue name: `messagesqueue` (use this exact name) → **Create**.
5. In the namespace, open **Shared access policies → RootManageSharedAccessKey** → copy the **Primary Connection String**. You need it in Part D.

---

## Part B — Create the Console App

1. Open Visual Studio → **Create a new project** → **Console App**.
   - Pick the one that says **.NET Framework** (Console App (.NET Framework)), language **C#**.
2. Project name: `ServiceBusQueueDemo` → Next.
3. Framework: **.NET Framework 4.8** (or 4.7.2) → Create.

These steps are the same in Visual Studio 2022 and in the newer 2026 editions.

## Part C — Install the NuGet Package (current, not deprecated)

1. **Tools → NuGet Package Manager → Manage NuGet Packages for Solution…**
2. Browse tab → search **`Azure.Messaging.ServiceBus`** (published by Microsoft) → Install latest stable (7.x).

That is the only package you need. NuGet adds its required parts automatically.

**Do not use these old ones** (they are marked deprecated):
`WindowsAzure.ServiceBus`, `Microsoft.Azure.ServiceBus`, `Microsoft.ServiceBus`.

## Part D — Code

Open `Program.cs`, delete everything, and paste this:

```csharp
using System;
using Azure.Messaging.ServiceBus;

namespace ServiceBusQueueDemo
{
    internal class Program
    {
        // Paste your Service Bus connection string here
        const string Conn = "Endpoint=sb://labservicebus2026.servicebus.windows.net/;SharedAccessKeyName=RootManageSharedAccessKey;SharedAccessKey=YOURKEY";

        // Must match the queue name in Azure
        const string Queue = "messagesqueue";

        static void Main(string[] args)
        {
            var client = new ServiceBusClient(Conn);

            if (args.Length > 0 && args[0] == "read")
            {
                var reader = client.CreateReceiver(Queue);
                var msg = reader.ReceiveMessageAsync().Result;
                if (msg == null) Console.WriteLine("Queue is empty.");
                else
                {
                    Console.WriteLine("Received: " + msg.Body.ToString());
                    reader.CompleteMessageAsync(msg).Wait();   // removes it from the queue
                }
            }
            else
            {
                var sender = client.CreateSender(Queue);
                sender.SendMessageAsync(new ServiceBusMessage("Hello from Service Bus Queue")).Wait();
                Console.WriteLine("Message sent. Now check Azure Portal.");
            }

            Console.ReadLine();
        }
    }
}
```

**About this code (plain words):**
- `ServiceBusClient` — connects to your namespace.
- `CreateSender` + `SendMessageAsync` — puts one message into the queue.
- `CreateReceiver` + `ReceiveMessageAsync` — takes one message out.
- `CompleteMessageAsync` — confirms the message and deletes it.
- Run with no argument → **sends**. Run with argument `read` → **receives**.

**About the `namespace` line in code:** `namespace ServiceBusQueueDemo` is just a C# name space for your code, same as the project name. It has no connection with the Azure Service Bus Namespace name.

**Small fix if needed:** if you see a "Could not load file or assembly" error, right-click the project → **Properties** → check **Auto-generate binding redirects** → Save → Build again.

---

## Part E — Run and Send

1. Paste your connection string into `Conn` (line 8).
2. **Ctrl + F5** (Start Without Debugging).
3. Output:

```
Message sent. Now check Azure Portal.
```

---

## Part F — Verify the Message in Azure

1. Login to **Azure Portal**.
2. Search **Service Bus**.
3. Select your Service Bus Namespace.
4. In the left pane, under **Entities**, click **Queues**.
5. Select your queue → **messagesqueue**.
6. You will see message count increased under **Active Message(s)**.

To read the body in the portal: open the queue → **Service Bus Explorer** (or **Messages**) → **Peek** → select the message → view body → you will see `Hello from Service Bus Queue`.

---

## Part G — Receive it from the app (optional)

1. **Project → Properties → Debug** → Command line arguments: `read`
   (or run from the bin folder: `ServiceBusQueueDemo.exe read`)
2. **Ctrl + F5** → Output:

```
Received: Hello from Service Bus Queue
```

3. Refresh the portal page → **Active Message(s)** count is back to 0.
